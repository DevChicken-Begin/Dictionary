# M09 — Retrieval identity, filters and evidence

Hydration previously scanned with `all` filters; multi-probe retrieval overwrote cosine with an RRF composite. Duplicate views could contribute multiple RRF votes per SKU/probe.

Changed server retrieval to preserve raw cosine as `similarity`/`raw_vector_similarity`; separate `retrieval_score`, RRF, consensus, probe IDs and view evidence. One vote per SKU/probe; identical query vectors are queried once. Bounded oversampling (at most 100 rows per probe) precedes collapse/filtering. Best-view geometry is retained and missing/non-finite identities discarded. Hydration forwards usage/view filters, checks returned metadata again and excludes orphan vectors. Query validates the enums actually present in the UI. No new RPC or production index operation.
