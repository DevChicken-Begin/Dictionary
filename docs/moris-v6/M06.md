# M06 — Embedding contract

Worker `embed-variants-v2` previously used patch pooling and pooled-only CLS replication under the same `cls_l2_v1` label. Browser fallback separately canonicalized at 448px, extracted CLS and attached that same label. Those representations cannot safely share an index.

## Change

- `moris-layer2-embedding.ts`/JS require exact supported spatial shapes, matching lengths and finite values. Pooled-only tensors fail; no replicated patches.
- Worker requires unpooled output. Browser propagates failure and validates profile, dimension, finiteness and unit norm.
- Hybrid identity is now `hybrid_gem3_edge_55_45_pseudorgb_u8_v1` with model `onnx-community/dinov2-small`, revision `ef1fb10`, preprocess `kim_canon_v2`, dimension 384: signed GeM p=3 and edge means, 0.55/0.45 fusion, pseudo-RGB channels quantized to uint8 before the model processor.
- Raw CLS API uses `raw_image_v1` / `cls_l2_raw_v1`, never hybrid identity. Server defaults and endpoint profile attestation agree; supplied legacy profile is rejected with 400. Zero/non-finite query vectors rejected.
- Existing RPC filters full profile identity. Legacy 1,090 vectors are untouched and not relabeled. New profile has no production index yet. If environment pins legacy profile, new browser requests fail closed; rollout must coordinate configuration and explicitly approved Center reindex. No automatic conversion is justified by dimension alone.
