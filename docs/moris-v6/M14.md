# M14 — Bounded optimal hole assignment

Replaced sort-by-X/index pairing with a Hungarian minimum-cost assignment. Coordinates contribute distance; available normalized radius/relative area and size class add cost. Dummy slots represent missing/extra holes. All transforms come from M13's chirality policy. Output includes matched pairs, unmatched indices, chosen transform, similarity, reliability and `hole_assignment_v2` version. Bad/unknown masks are unavailable; count-only legacy evidence has reduced reliability. No SKU-specific rule.

Assignment is capped at 64 holes, O(n³), with finite/nonnegative matrix validation. The matching formulation follows the minimum-weight bipartite assignment contract described in [SciPy's official reference](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linear_sum_assignment.html); implementation is local JavaScript, no new package/service.

Actual tests **353/353**, 33 files; TypeScript/build exit 0, 46 static files (`M14-*.log`). Optimality verified against exhaustive permutations for sizes 1–5 across deterministic costs. Tests include same-X/different-Y, permutations, missing holes, radius/type mismatch, 17-vs-5, bounded 64-hole work and deterministic output. Synthetic local CPU benchmark, 100 runs of 64 holes: p50 **2.445 ms**, p95 **5.107 ms**, max **22.272 ms** (`M14-assignment-benchmark.json`). These timings are not device/camera p95.

Real hard-negative quality/ablation remains pending curated M21/M22 data; no improvement claim. No production writes/storage increase/deploy/commit; branch/HEAD unchanged. Rollback matching module/copy and geometric adapters/tests, rebuild; keep M13 policy. Next M15.
