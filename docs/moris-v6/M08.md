# M08 — Nullable geometry and audit

## Changes and evidence

Worker emits `geometry_v1` with optical provenance, normalized coordinate space, raster scale and measured mask-quality flags. Unreliable masks suppress counts, centroids, aspect and EFD rather than producing zero. The same validated nullable contract is used in browser and server. Hydration preserves unknown values; structural and geometric scoring do not award or penalize unavailable counts/aspect. Trusted measured zero is retained; legacy unversioned zero/text recovery remains separately identifiable until ranking cleanup.

Center passes geometry to the API. Inspection found the existing SQL writer/search RPC coalesces null to 0/1. Until M23's reviewed nullable persistence/read contract, indexing rejects unknown/unreliable geometry rather than knowingly storing invented values. No production SQL changed. This intentionally means an unreliable image must be replaced/retaken for indexing; query embeddings can still search without geometric evidence. Existing reliable index identity/count behavior remains unchanged.

Actual READ ONLY audit: **55/545** front/thumb count mismatches, list of hashed record references in `evidence/M08-geometry-audit.json`. Different views can hide holes; neither side is automatically designated correct. Curator workflow: resolve each hash against authorized catalogue, inspect both original assets, label visibility/count and provenance, record uncertainty, then use explicit Center replacement after migration approval. No mass correction.
