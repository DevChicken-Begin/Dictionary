# M10 — Complete bounded catalogue paging

Frontend ID/code/feature filtering previously requested 2,000 rows once while SQL capped each call at 300. `scanFilteredCatalogue` now reads pages of at most 300, deduplicates IDs, cancels superseded requests and explicitly errors on stuck pages or the 10,000-row budget instead of reporting partial data as complete. Ordinary 36-row UI paging is unchanged. Server scans also use bounded pages, filters, deduplication and explicit overflow detection.

The existing RPC sorted only timestamp ties. CLI-generated proposal `20261016033020_moris_v6_catalogue_stable_paging.sql` preserves its interface, auth guard, feature matching and cap, adding ID to both inner and final ordering. Production has not been changed. Until this proposal is applied with review, timestamp tie ordering remains a production limitation; concurrent catalogue edits during offset paging still require a retry/snapshot strategy at larger scale.
